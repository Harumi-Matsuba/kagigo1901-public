# 方法・数字・AI の使用・限界

## 1. 電報の見つけ方
- 出発点は、訳文付きの部分暗号の電報 C09122806100（1901-02）と、目録の検索で見つけた C09122909900（1902-03）。
- JACAR の全文検索は、目録の内容欄の冒頭しか引かない。さらに参謀本部 雑（秘）の綴では、内容欄そのものが約320字で打ち切られている。そこで次の範囲を、画像で1コマずつ見た（取得は3秒以上の間隔）。
  - 参謀本部 雑（秘）『明治３４年・３５年 電報綴 北清事件』と同年の通報綴：画像が取れた件の全部（約420件、1,088コマ。404 が5件）。
  - 陸軍省大日記の1904年の着電のうち、JACAR の検索で「訳文」「電報訳」に当たった235件（1,749コマ。404 が3件）。
  - 目録の内容欄 約2,200件で、数字の列と「2桁の漢数字が読点で並ぶ」翻刻を検索した。C09123116600 はこれで見つけた。
- 見つかった数字のカナ暗号の電報は5通（訳文あり4、訳文なし1）。ほかに5桁の数字とローマ字の電報（参謀本部→福島少将など4通、別の方式）があった。括弧付きのカナ2字の群は、料金節約のための『陸軍電信符号』で、暗号ではない（Cryptiana の記述と訳文で確かめた）。

## 2. 表の推定
- C09122909900 の12組と往電の振り仮名（カイグンエンシウケンガク）から、次のことが分かった：ン は3回とも 10。頭の数字を5で割った余りが母音とそろう（a0・i1・u2・e3）。頭が5以上は濁音だけ。カ行の後ろの数字は清音 8・濁音 9。
- 行の数字が ア9 カ8 サ7 と並ぶので、五十音の逆順とみて表を作った。その後に見つけた C09122911500 で、表は35組すべてに当たった（バ行の列 6 はこの電報の ブ から決めた）。
- C09122806100（1901-02）には、この表も、表に周期1〜7の数字を足す方式も合わない。

## 3. 対照
- 入れ替えの対照（`src/table1902.py`）：段の数字5つ・行の数字10・濁音の行の数字4つを無作為に入れ替えた表で、訳文との一致が本物以上になる回数を1000回数えた。C09122911500 0回（最大16、本物35）、C09122909900 0回（最大7、本物11。ただし表をこの電報から作ったので目安）、C03020059400 0回（最大5、本物12。2026-10-25 の訂正の前は本物10）。
- 訳文のない C09123116600：JACAR の目録の内容欄から平文の電報のカナ（18,810字）を集め、カナ2字の連なりの尤度を作った。本物の表の読み（−42.8）以上になった入れ替えの表は1000回中0回、最良は −46.0。学習用のカナは JACAR の目録の文なので、このリポジトリには入れていない。
  - 最初の版では、表で ン と ヰ がどちらも10になり、読みに ヰ が出て、本物以上が12回になった。ン を優先し、表にない値に罰点を付ける形に直してから回した値が上の 0回。

## 4. 独立の2回目の書き起こし
- 1回目は Claude Opus 5.5 が画像を拡大して読んだ。2回目は、画像と指示（`second/PROMPT*.md`）だけを渡し、値・1回目の読み・訳文は渡さずに、別のモデルに読ませた。
  - OpenAI Codex（codex-cli 0.163.0-alpha.10.2、モデルは実行記録に出ないので既定のモデル）：`codex exec --ephemeral -s read-only -i <画像>`、プロンプトは標準入力。実行記録に、コマンドの実行やファイルの読み込みはない。
  - Claude Sonnet：Claude Code の Agent（model=sonnet）。画像のパスと同じ指示だけを渡した。
- 比べるのは数字だけ。列ごとの編集距離で数え、一致率＝(基準の字数−編集数)/基準の字数（`src/score.py`）。候補付き [a/b] は最初の候補、? は誤り。本文にない書き込みを字として入れた場合も誤りに数える（C09122909900 の2度目の取り直しの前に、この数え方を決めて記録した）。
- 全部の値を書き、判定には最も低い値を使う。

| 電報 | 回と値 | 最低値 |
|---|---|---|
| C09122911500（72字） | Codex 100%・97.2% | 97.2% |
| C09123116600（26字） | Codex 100%・100% | 100% |
| C09122909900（26字） | 拡大前：Codex 92.3%・92.3%、Sonnet 84.6%。拡大後：Codex 96.2%・100%・100%・100%、Sonnet 88.5%・84.6%・92.3%・92.3% | 84.6% |
| C03020059400（24字） | 拡大前：Sonnet 87.5%。拡大後：Codex 95.8%・95.8%・91.7%、Sonnet 91.7%・87.5% | 87.5% |

- 食い違いの字は、1字ずつ切り出して値を伏せ、Codex と Sonnet（別の文脈で2回）に判定させた。2つの判定がそろって1回目と違う字になった所はなく、1回目は直していない（直した数0）。

## 5. 較正
- 当時の訳文（3通）と往電の振り仮名（C09122909900）を較正に使った。文字の一致：C09122911500 35/35、C09122909900 11/12、C03020059400 12/12（2026-10-25 に友清理士氏の目視で1字を直し、ゼウ を綴りとみた後。以前は 10/12）。C09123116600 は訳文がないので較正なし。

## 6. 鑰号との関係（推定）
- 鑰号暗号は1900年6月印刷、物号の改正で、1901年1月から1904年6月まで使われた（JACAR C09122592800・C10061983200・C06040646600）。使用中の1900年9月に「秘密ヲ守ルノ点ニ於テハ頗ル確実ナルモ使用上甚タ不便」とされた。附属の「乙号」には参謀が暗記する「鑰語標点」があった（C02030445900、1901-03）。
- この表は単純で、1902年3月から1904年1月まで変わっていない。鍵（鑰語）で値を変える方式の、鍵なしの使い方なのか、別の暗号（坤号の後継とみられる特号の「数字ノ分」、C03025477100）なのかは決められない。

## 7. 限界
- 人の確認は一部だけ：友清理士氏が画像を目で見た読みを Cryptiana に載せた（2026-10-24）。それに従って1字を直した。AI どうしの一致は、人の確認の代わりにならない。
- 標本は4通（66組）。表の値のうち、実際に出たのは一部（ア・カ・サ・タ・ナ・ハ・マ・ヤ・ラ・ワ行の一部と濁音のガ・ザ・ダ・バ行の一部）。出ていない値は、規則からの推定。
- JACAR の画像は二値化（JBIG2）されていて、細い印や濁点の有無は分かりにくい。
- 通覧は上の範囲に限る。陸軍省大日記の1904年の綴のうち、検索に当たらなかった件は見ていない。

## 8. AI の使用

- OpenAI Codex：独立の2回目の書き起こし、字の判定。
- Claude Sonnet：独立の2回目の書き起こし、字の判定、先行の調べ（解読に加わっていない別の文脈）。
- 公開者：作業の方針の指示。書き起こしと読みの確認はしていない。

## 9. 1901年の表（2026-11-10 に追加）
対応と読みは [READING1901.md](READING1901.md)、スクリプトは `src/table1901.py`。

### 9.1 見つけ方
- 清国駐在の将校との欧文電報（ローマ字の日本語）に、5桁の数字の群が混じる。2026-10 の通覧では、これらを平文のローマ字の電報とみて、数字を見落としていた。
- 訳文の付いた C09122724200 で、数字の2本がどちらも14桁（5・5・4桁）で、訳文の語（独逸皇帝・天皇陛下）のカナ7字ずつに当たる。5桁の区切りは送るときの体裁で、単位は2桁と分かった。発信側の起案5通でも、数字の連なり23本がどれも偶数桁になる。
- 福島少将の着電4通（C09122805800・805900・806000・801000）は、同じ綴に訳文があり、受け手が数字の脇にカナを書き込んでいる。訳文の語と書き込みから値を集めると、ア00 カ01 ガ02 サ03 … と五十音の段ごとの連番になっていて、濁音が清音の直後に入る（タ05 ダ06、ゲ42、ゼ44、ド59）ことが分かった。この規則で 00〜67 を埋めた。

### 9.2 対照
- **表を決めた後に当てた2通**（表の推定に使っていない）：C09122796200 の10組と、C09122806100 のうち表の中の値だけでできた2本（ンチワ・フクム）の6組。期待されるカナ（訳文の語を電報の綴りで書いたもの）と 16/16 一致。表の68字を無作為に並べ替えた表では、1000回中0回しか本物以上にならなかった（最大4）。
- C09122796200 の モ・ト・グ は、ほかの電報に出てこない値で、並びの規則だけから先に決まっていた。
- 表の推定に使った4通は 42/42（表を作るのに使ったので、確かめにはならない）。C09122724200 の14組は、表が分かってから読み直した桁を含むので、数に入れていない。
- 期待されるカナの綴り（ヲ→オ、助詞のハ→ハかワ）は、読んだ後で決めた。この点は答えを見ずに決めたものではない。

### 9.3 独立の2回目の書き起こし
- OpenAI の Codex（codex-cli 0.163.0-alpha.10.2、モデル gpt-6-astra、推論の深さ high）に、着電6通の本文欄の画像を1枚ずつ、空のフォルダから渡した。表・1回目の読み・訳文は渡していない。実行記録にコマンドの実行やファイルの読み込みはない。依頼文は `second/PROMPT1901.md`、返答は `second/codex1901/`（run1_＝1回目の6枚、run2_＝拡大した4枚）。画像には受け手のカナの書き込みが写っている（依頼文で無視するよう指示した）。
- 数字の桁の一致（1回目の読みを基準、編集距離）：6通の合計 123/135（91.1%）。電報ごとに C09122805800 48/49、C09122805900 7/8、C09122806000 8/8、C09122796200 19/20、C09122801000 17/22（77.3%）、C09122724200 24/28（85.7%）。
- 食い違った桁は、1回目の読み手（Claude）が拡大した画像で見直し、1回目のままとした（直した桁は0）。別のモデルによる判定はしていない。
- 一致の低かった2通（C09122801000・C09122724200）は、上2行を左右に切って拡大した画像4枚で、同じ依頼文のままもう一度読ませた。切り口で群が分かれ、返答は断片になった：C09122801000 は切り出しに入った20桁のうち 15/20（75.0%）、C09122724200 は 25/28（89.3%）。良い回だけを選ばず、どちらの回も載せる。
- したがって C09122801000（ゲンスイガ・コウテイヨリ）は、2回目との一致が 75.0〜77.3% で 90% に届かない。C09122724200 は、Codex が2回とも1本目の2群目の前に「7」を読み（59153 7 25427 4515）、2本目の頭の群を 4507x と読んだ。こちらの読み（59153 25427 4515、45676）は表が分かってからのもので、この2点は決着していない。表の値のうちこの2通だけに出るもの（カ・ガ・リ・ス・ツ・ゲ・ヘ・コ・ド・ヨ の10個）は、その分だけ弱い。
- 当時の訳文と受け手の書き込みがあるので、読みの正しさはそちらで支える。AI どうしの一致は、人の確認の代わりにならない。

### 9.4 限界
- 人は書き起こしを確かめていない。
- 標本は7通・72組（C09122806100 の表の外の値を除く）。電報で確かめた値は68個のうち38個。
- 当時読まれていた電報なので、ここで新しいのは表の復元だけ。表の名前（特号暗号の数字の分か）は確かめられていない。
- 発信側の起案5通は読めていない（[OPEN.md](OPEN.md)）。
